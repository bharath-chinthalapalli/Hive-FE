The Hive map can be configured to 3 special dimensions as can be shown in Figure 7. In this figure the Cells composing the map are arranged along the X, Y and Z axis. In this configuration the encryption path can travel across the three axes. This configuration allows higher level of complexity and increasing the confusion and diffusion level in the map.

Figure 7: Conceptual model of 3D Hive Space with encryption path propagating in all three dimensions
As per this compilation the number of Cells within the map is equal to: Number of Cells = Cx × Cy × Cz Where Cx is number of Cells along X axis, Cy is the number of Cells along Y axis and Cz is the number of Cells along Z axis. The number of possible encryption path is equals to: Number of encryption path = 2 number of cells

In terms of implementation the 3D can be programmed in the same way as the 2D map except with the following differences:

The map is represented by three dimensional array declared as the following EncryptionCell HiveMap[Cx] [Cy] [Cz]; Where Cx, Cy and Cz are integers represents number of Cells in each axis
The path is generated by mathematical manipulation of the indices of the map's array within the Path Generation Function

In addition to three-dimensional configuration, the Hive map can be configured for a four or more dimensions, three spatial and one time so that the encryption will depends on both the encryption path and on the time of the encryption. This can be implemented by enabling the map to continuously change over time by shifting of the Cells location and/or the encryption value within the Cells. This configuration will allow for real-time and non-reversible map encryption ideal for a dedicated one-toone communications session between two end users.

To ensure correctness of encryption process, the following should be considered:

Whenever the sending map undertakes any timely change the receiving map must be informed in order to undertake the same change. This can happen through exchanging defined encrypted messages in the middle of the encryption process
The change to Hive map will undertake is irreversible
In addition to an Encryption Path Generation function, the system must implement a Map Evolution Function to be one of the Hive Map's properties.
In order to make the Map Evolution Process unique to each communication session it can be based on initial parameter derived from a common information between the sender and the receive (for example the Encryption Key)

The Hive map can be configured to more than 4-dimensions in terms of time and space however this will require a programming language that supports more than 3 dimensional array manipulations. In this configuration, the Hive map will take the shape of conceptual 4D shapes such as tesseract or a hypersphere supported by modern mathematical models of such shapes. However, the map will work on exactly on the same principle as 2D or 3D map the only difference the Encryption Path Generation Function and the Map Evolution Function will have to be programmed for such hyper shapes.
