The worldwide proliferation of large quantity of data transmitted in the open information and communication technology (ICT) infrastructure, especially the Internet, has thrust information security to the forefront of attention from the academic researchers, industry practitioners, as well as government agencies around the globe (e.g., Appari and Johnson, 2010; Halperin and Backhouse, 2008; Dlamini et al., 2009). Various legislative bodies have stipulated the protection of sensitive data (e.g., the HIPPA regulation for health related data, and the Sarbane-Oxley legislation for financial data). Researchers have developed a wide variety of technical (e.g., Ahmad et al 2012; Ford and Baum 2000; Scarfone et al. 2008), behavioral (e.g., Crossler et al., 2013; Mai et al., 2017; Herath and Rao, 2009), and economic (e.g., Anderson and Moore, 2006; Jerman-Blazic, 2008; Mai et al., 2016) tools and mechanisms to ensure information security, and business organizations have embraced the challenge of information security and have heavily invested to improve the security of their business information.


Among the different information security tools and mechanisms available, encryption is one of the most fundamentally established and universally adopted systems used to improve information security (e.g., Rogaway and Coppersmith, 1998; Wang and Yu, 2009; Bosch et al., 2015; Schneier, 1993; Zhang et al. 2005). The continuous advancement of information and communication technology had enabled the development of more and more advanced encryption systems


Generally speaking, encryption algorithms can be classified into two types: symmetric key encryption (i.e., private key encryption) and asymmetric key encryption (i.e., public key encryption). Symmetric key encryption has the significant advantage of high efficiency of implementation, but faces a fundamental disadvantage of key management necessary for secure implementation. To address this disadvantage, asymmetric key encryption has been developed. While asymmetric key encryption has successfully addressed the key distribution issue of symmetric key encryption, the implementation of asymmetric key encryption is significantly less efficient. As a result, today's encryption systems are mostly a hybrid system (Mao 2003, 2006; Stallings, 2006), in which symmetric key encryption is used to encrypt the communication messages, while the related private key used is encrypted using asymmetric key encryption.


Symmetric key encryption is implemented as either block encryption or stream encryption, the former of which encrypts inputs in blocks of plaintext, and the latter of which encrypts inputs by individual characters.


Modern stream encryption is based on one model by which the plain text is logically combined with a pseudorandom key-stream on bits level (e.g., Daemen and Clapp 1998; Min and Chen, 2013). However, due to many weaknesses resulted mostly from the mathematical dependencies of the model, stream encryptions have never achieved the level of reliability and confidence that would allow them to be applied more extensively in modern computing (e.g., Daemen et al., 1993).


All modern stream encryption systems are based on the famous "One-Time-Pad" (OTP) encryption (Hammersmith 2002) by which the plain text is encrypted letter by letter using a key-stream that is of the same size as the plain text through direct mapping. The key-stream is generated randomly and only used once and has no mathematical relation neither with the plain text nor the outcome, which makes the "one-pad" encryption theoretically mathematically unbreakable. However, this comes with significant implementation requirements that make it expensive to implement and very limited to high end application (e.g., Rueppe,l 1986).


Therefore, the OTP concept was implemented differently by which the key-stream is generated one a pseudorandom manner through a logical function and combined bitby-bit with the plain text using logical operation such Exclusive OR (XOR). Due to this logical dependency, modern stream encryptions have inherited vulnerabilities such as repetitive key-stream, encryption key can't be re-used and detectable mathematical functions. All these limitation has made cipher encryption breakable and unreliable for heavy applications. On the other hand, block cipher offers much stronger encryption however due its bulky nature that is based on encrypting big chunks of data at once, it has limited application in real-time and stream communications. Hence, developing a new stream encryption that offers "one-timepad" strength and efficiency would enable many new and reliable real time applications for encryptions.


We present the design of a new stream encryption method that offers the strength and complexity to overcome the weaknesses and shortfall in current stream encryption methods using a new symmetric encryption model that encrypts/decrypts information along a path through multi-dimensional numeric space composed of cells arranged to form one encryption map. The main idea is to eliminate any mathematical relationship between the path and the encryption values in the cells in order to eliminate most of the issues found in the current classic stream encryption methods. Unlike modern stream encryption, the present invention uses the 2D/3D & 4D numeric map as an encryption function and the encryption path as a key-stream. The path is generated from a symmetric secrete encryption key shared between the sender and the receiver, who both share the same encryption map with its parameters. The encryption map parameters has to be designed to yield complexity that would make breaking the encoding computationally infeasible even using today's fastest supercomputers. Another fundamental difference between present invention and current stream encryption methods is that encryption/decryption process is taking place on the Unicode characters hexadecimal values (4-bits at a time) instead of 1-bit at time, which makes the encryption process more complex to break against traditional attacks yet faster and more efficient.

The proposed encryption algorithm can be visualized by a map of hexadecimal numbers arranged into encryption cells. Figure 1 shows an example of such an encryption cell that makes up the Hive encryption map. As shown in the Figure 1, each cell (denoted by its cell index (1)) is of a hexagon shape contains 16 Encryption Point (2) along its 6 sides. Each Encryption Point (2) has two values; the Plain Text Value (3) and the Cipher Text Value (4). The present encryption is Hexadecimal based where encryption is taking place 4-bits at a time instead of bit by bit basis.

At an Encryption Point the encryption process takes place by direct mapping of the hexadecimal number represented in the Plain Text Value (3) with the corresponding hexadecimal number represented in the Cipher Text Value (4).

In actual implementation, there will be a Hive encryption map consisting of multiple encryption cells like the one depicted in Figure 1. For example, Figure 2 illustrates a Hive encryption map that is composed of 12 encryption cells. The map is constructed such that the Cipher Text Values within the Encryption Cells can either be generated randomly (Confusion) or by constantly shifting these values, within copies of the randomly generated cells, one step in clock-wise direction (Diffusion). For example the Encryption Cell number 12 is generated randomly and Encryption Cell number 1 the Cipher Text Value is the same value as Encryption Cell number 12 but shifted one step clock-wise. So in Cell number 12 the Plain Text Value of 0x0 is encrypted by 0xA of Cipher Text Value, however in cell number 1 0x0 is encrypted by 0x6 and so on. Also Figure 2 shows the Encryption Path (4) in the map, which represents the order of cells the encryption process will take place in, and in this case it is 1→2→7→3→4→9→8→5→6→11→10→12.

The Hive Encryption map has the following properties:

Scalable Complexity: the complexity of the map can be scaled and managed easily as it’s a matter of increasing the number of the encryption cells. The complexity of map is measured by the possible number of path it contains which can be calculated as the following example: Number of Possible Encryption Path = 2n , 3 n , 4n , where n is number of encryption cells. So for example for a 2,000 cells map, the number of possible encryption path will be 22,000 = 1.2 x 10602 unique paths capable of encrypting more than 2.2 x10587 TB of data before the path repeats itself again.

Confusion and Diffusion: by either generating the Cipher Text Values randomly (Confusion) or by rotating them the Cipher Text Value of the randomly generated Encryption Cells one step clockwise (Diffusion). The resulted cipher will be scrambled and looks totally random from external attacker’s point of view.

Encryption Path Generation Function: the encryption key is used as a seed for generating the required path for encrypting the plain text. This function is unique and its consistence is such that when the sender and the receiver use two copies of the same map and the symmetric encryption keys the generated path will be the same at both ends.

Encryption Map Tuning Function: In order to ensure each encryption session is unique and will generate different set of encryption data the map has to be tuned each time it's used. To implement that the map will use Encryption Map Tuning Function, by which the cells within the map can be re-arranged accordingly. This function enables changing and scrambling the values of the map to create a new topology of the map to enable the re-use of the same map between the same users more than one time.

The Encryption Path is generated from the cells’ numbers according to a function that associated with the Hive map. This function is responsible for generating the Encryption Path using the encryption key that will be shared between the sender and receiver. To achieve this, the encryption key itself is a subset of the encryption path and represents the first part of the path.

A Hive encryption protocol would operate as the following steps:

  1. The process starts by the sender and the receiver getting copy of a common Hive map they will use for the encryption / decryption of data between them. This common Hive map will be standard and would be found on the World Wide Web and come with different sizes and Encryption Path Function;
  2. The sender then, for the first time during the setup of the encryption, will tune the map using set of define parameters or initiation vector in order to customize it for the communication with the receiver;
  3. The sender then will send the tuning parameters or initiation vector to the receiver;
  4. The receiver will in turn tune the map to be identical to the sender’s map;
  5. The sender then generates from the map an Encryption Key that will be used symmetrically with the receiver for the encryption process. The size of the key can vary depending on the agreed parameters between the sender and receiver;
  6. After generating the encryption key the sender will then send it to the receiver over a secure channel using any of the known standard methods for exchanging secret symmetric keys;
  7. The sender then will use the encryption key along with the map to encrypt the plain text he/she would like to send. The map will work on the same dynamic explained above by taking the encryption key as a seed to generate the required length of the encryption path in accordance with the map’s path function as explained using Figure 3.
  8. The encryption process takes place and the cipher text is streamed down the (unsecure) communication channel between the sender and the received. Given the dynamic of the Hive encryption, there is no limitation in the length of the encryption process that will go on as long as it’s needed.
  9. The receiver will then uses the Hive map and the encryption key to decrypt the cipher text into the original plain text that was sent.

In terms of implementation, the proposed algorithm can be programmed using structured programming language (such as C) or object oriented language (such as C++ or C#) as the following brief design outline:

  1. Encryption Cells can be programmed as user-define structure type as the following:
    Struct EncryptionCell { Int CellNumber; Unsigned char plainTextValues [16]; Unsigned char cipherTextValue [16]; }
  2. The Hive map can be coded as one dimensional array or EncryptionCell type as the following:
    EncryptionCell HiveMap [MAP_SIZE];
  3. The encryption process can be initiated by creating the encryption path using the encryption key as the following:
    CreateEncryptionPath (EncryptionKey key1);
  4. After the generation of the encryption path the process can start as the following:

    while ((plainTextHexChar = getCharFromStream()) != EndOfStream) { cipherTextHexChar = HiveMap[plainTextHexChar]; sendCipher(cipherTextHexChar); moveToNextEncryptionCellOnPath(); }

  5. The decryption will the reverse of the encryption process and can be programmed in the same way. To enable the re-use of the encryption key this invention uses two mechanisms:
  6. Use of time stamp that can be used in conjunction with the encryption key to generate a unique encryption path depending on the time of the communication session;
  7. Use dynamic cell padding by assigning random values to the outcome produced by some selected encryption cells that yield different stream cipher if the key is reused.

In this paper, we propose a new stream encryption algorithm, Hive Stream Encryption (HSE) that improves upon the existing stream encryption methods. The core of HSE is a new symmetric encryption model that encrypts/decrypts information along a path through multi-dimensional numeric space composed of cells arranged to form one encryption map. We show that HSE is able to eliminate any mathematical relationship between the path and the encryption values in the cells and as a result, can eliminate most of the issues inherited in the current classic stream encryption methods.
