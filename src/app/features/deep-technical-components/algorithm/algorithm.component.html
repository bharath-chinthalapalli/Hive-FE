Algorithm Description
The proposed encryption algorithm can be visualized by a map of hexadecimal numbers arranged into encryption cells. Figure 1 shows an example of such an encryption cell that makes up the HIVE encryption map. As shown in the Figure 1, each cell (denoted by its cell index (1)) is of a hexagon shape contains 16 Encryption Point (2) along its 6 sides. Each encryption Point (2) has two values the plain text value (3) and the cipher text value (4). The present encryption is hexadecimal based where encryption is taking place 4-bits at a time instead of bit by bit basis.At an encryption point the encryption process takes place by direct mapping of the hexadecimal number represented in the plain text value (3) with the corresponding hexadecimal number represented in the cipher text value (4).In actual implementation, there will be a HIVE encryption map consisting of multiple encryption cells like the one depicted in Figure 1. For example, figure 2 illustrates a HIVE encryption map that is composed of 12 encryption cells. The map is constructed such that the cipher text values within the encryption cells can either be generated randomly (confusion) or by constantly shifting these values, within copies of the randomly generated cells, one step in clock-wise direction (diffusion). For example the encryption cell number 12 is generated randomly and encryption cell number 1 the cipher text value is the same value as encryption cell number 12 but shifted one step clock-wise. So in cell number 12 the plain text value of 0x0 is encrypted by 0xA of cipher Text value, however in cell number 1 0x0 is encrypted by 0x6 and so on. also Figure 2 shows the Encryption Path (4) in the map, which represents the order of cells the encryption process will take place in, and in this case it is 1→2→7→3→4→9→8→5→6→11→10→12.
The HIVE encryption map has the following properties:
Scalable complexity: the complexity of the map can be scaled and managed easily as it's a matter of increasing the number of the encryption cells. The complexity of map is measured by the possible number of path it contains which can be calculated as the following example:number of possible encryption Path = 2n, 3n, 4n, where n is number of encryption cells. So for example for a 2,000 cells map, the number of possible encryption path will be 22,000 = 1.2 x 10602 unique paths capable of encrypting more than 2.2 x10587 TB of data before the path repeats itself again.
Confusion and diffusion: by either generating the cipher Text values randomly (confusion) or by rotating them the cipher text Value of the randomly generated encryption cells one step clockwise (diffusion). The resulted cipher will be scrambled and looks totally random from external attacker's point of view.
Encryption path generation function: the encryption key is used as a seed for generating the required path for encrypting the plain text.This function is unique and its consistence is such that when the sender and the receiver use two copies of the same map and the symmetric encryption keys the generated path will be the same at both ends.
The encryption path is generated from the cells numbers according to a function that associated with the HIVE map. This function is responsible for generating the encryption Path using the encryption key that will be shared between the sender and receiver. To achieve this, the encryption key itself is a subset of the encryption path and represents the first part of the path.
A. HIVE encryption protocol would operate as the following steps:
  1. The process starts by the sender and the receiver getting copy of a common HIVE map they will use for the encryption / decryption of data between them. This common HIVE map will be standard and would be found on the World Wide Web and come with different sizes and encryption path function
  2. The sender then, for the first time during the setup of the encryption, will tune the map using set of define parameters or initiation vector in order to customize it for the communication with the receiver
  3. The sender then will send the tuning parameters or initiation vector to the receiver.
  4. The receiver will in turn tune the map to be identical to the sender's map
  5. The sender then generates from the map an encryption key that will be used symmetrically with the receiver for the encryption process. The size of the key can vary depending on the agreed parameters between the sender and receiver.
  6. After generating the encryption key the sender will then send it to the receiver over a secure channel using any of the known standard methods for exchanging secret symmetric keys.
  7. The sender then will use the encryption key along with the map to encrypt the plain text he/she would like to send. The map will work on the same dynamic explained above by taking the encryption key as a seed to generate the required length of the encryption path in accordance with the map's path function as explained using Figure 3.
  8. The encryption process takes place and the cipher text is streamed down the (unsecure) communication channel between the sender and the received. Given the dynamic of the HIVE encryption, there is no limitation in the length of the encryption process that will go on as long as it's needed.
  9. The receiver will then uses the HIVE map and the encryption key to decrypt the cipher text into the original plain text that was sent.
